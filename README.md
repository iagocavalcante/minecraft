# Minecraft

A Minecraft server implementation in Elixir supporting both **Java Edition** (1.12.2, Protocol 340) and **Bedrock Edition** (1.26.30, Protocol 1001).

> **Fork of [thecodeboss/minecraft](https://github.com/thecodeboss/minecraft)** — original by Michael Oliver. This fork adds full Bedrock Edition support (verified against real mobile clients), upgrades dependencies to modern Elixir/OTP, and hardens the protocol paths.

Until this reaches version 1.0, please do not consider it ready for running real Minecraft servers (unless you're adventurous).

You can view [the documentation on Hex](https://hexdocs.pm/minecraft/).

## What works today

A real phone running Minecraft Bedrock 1.26.x can join over LAN and:

- complete the full join sequence (RakNet, login, resource packs, StartGame)
- render the NIF-generated world: Perlin terrain with water, sand, dirt, grass and Voronoi biomes (ocean, plains, desert, forest, taiga, swamp, ice plains, jungle, birch forest)
- walk an effectively infinite world — chunks generate and stream as the player moves
- break blocks (server-authoritative, applied to the shared world and persisted while the server runs)
- place blocks (stone-only until the item pipeline lands, see Phase 3)

Java Edition 1.12.2 clients get the original feature set: login with encryption, chunk streaming, movement, chat and keep-alive (see the Java checklist below).

Both editions share one world: terrain is generated by C NIFs (Perlin heightmap + Voronoi biomes) and block mutations go through a single `Minecraft.World` process.

## Architecture notes

- **OTP**: one supervision tree; per-connection processes (`ranch` for Java TCP, a `gen_udp` listener + per-client session GenServers for Bedrock/RakNet).
- **C NIFs** (`src/`): terrain generation and chunk serialization, running on dirty CPU schedulers.
- **Bedrock block IDs**: the server sets `UseBlockNetworkIDHashes` and computes FNV-1a network block hashes (`Minecraft.Bedrock.BlockHash`), so no per-game-version runtime-ID tables are needed.
- **Reference implementations**: Bedrock wire formats follow [gophertunnel](https://github.com/Sandertv/gophertunnel) and [dragonfly](https://github.com/df-mc/dragonfly); divergences observed in the wild are documented in code comments.

## Running

Native (Elixir 1.17+ / OTP 27+, a C toolchain for the NIFs):

```sh
mix deps.get
mix run --no-halt
```

Docker:

```sh
docker build -t minecraft:local .
docker run -d --name minecraft --restart unless-stopped \
  -p 25565:25565/tcp -p 19132:19132/udp minecraft:local
```

Ports: `25565/tcp` (Java), `19132/udp` (Bedrock). On your phone: Play → Servers → Add Server → your host's LAN IP, port 19132.

## Testing

```sh
mix test
```

Protocol-level verification uses a headless Bedrock client (Node.js, [bedrock-protocol](https://github.com/PrismarineJS/bedrock-protocol)):

```sh
cd scripts/headless-client && npm install
node connect.js   [host] [port]   # joins and asserts the full spawn sequence
node interact.js  [host] [port]   # breaks + places a block, asserts server confirmations
```

Both scripts exit 0 on success, making them usable in CI.

## Roadmap

### Phase 1 — Bedrock join & world rendering ✅

- [x] RakNet layer (offline handshake, frame sets, splits, ACK/NAK decode, disconnect)
- [x] Protocol 1001 join sequence (NetworkSettings, login, resource packs, StartGame)
- [x] Chunk encoding (sub-chunk v9, paletted storages, hashed block runtime IDs)
- [x] Real terrain + spawn placed on the generated surface
- [x] Headless client test harness

### Phase 2 — World interaction ✅

- [x] Player movement tracking (PlayerAuthInput)
- [x] Block breaking (server-auth block actions and legacy InventoryTransaction paths)
- [x] Block placing (mechanism + UpdateBlock confirmations; stone-only for now)
- [x] Real biomes in Bedrock chunks
- [x] Chunk streaming as the player moves

### Phase 3 — Items & creative inventory

- [ ] ItemRegistry with the real vanilla item list (mobile clients need it for inventory UI)
- [ ] CreativeContent so the creative inventory is browsable
- [ ] Map the held item to the placed block (replaces the stone-only fallback)
- [ ] Pin down the held-item wire format from real-device captures (two variants exist in the wild; the decoder currently accepts both)

### Phase 4 — World persistence

- [ ] Persist block mutations and generated chunks to disk (the current term storage predates the NIF chunk resources)
- [ ] Load the world on boot; Docker volume documentation
- [ ] Periodic autosave + save on shutdown

### Phase 5 — Multiplayer

- [ ] PlayerList / AddPlayer / MovePlayer broadcast (Bedrock)
- [ ] Broadcast block changes to all connected sessions (both editions)
- [ ] Cross-edition visibility (Java and Bedrock players see each other)
- [ ] Bedrock chat

### Phase 6 — Gameplay depth

- [ ] Survival-mode breaking (timed breaking, crack progress)
- [ ] Server-side inventory state
- [ ] Day/night cycle for Bedrock (SetTime)
- [ ] Health, fall damage, void handling
- [ ] Basic entities/mobs

### Phase 7 — Operations

- [ ] Bedrock session keep-alive/timeout (dead sessions currently linger until disconnect)
- [ ] RakNet reliability: retransmit on NAK, ordered-channel enforcement
- [ ] Remote play beyond LAN (Tailscale or port-forward; the HTTP-only tunnel can't carry UDP)
- [ ] Metrics/observability
